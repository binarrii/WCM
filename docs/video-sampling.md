# 视频采样与窗口审核

默认使用场景采样与整窗审核：同一镜头内保留变化帧，将最多三张选中图片组成不重叠窗口，Qwen 一次描述整个窗口。OCR 和人脸分别检查窗口内所选图片，并在同一任务内复用完全相同输入的成功结果。

## 时间与覆盖

- 每帧解码后读取 `CAP_PROP_POS_MSEC`，在 `0、interval、2×interval…` 的绝对网格上选取到达时刻的第一帧，避免非整数 FPS 漂移。
- 结果保留真实采样时间到毫秒。可变帧率和较大 PTS 间隔不会复制帧；无效或倒退 PTS 从最近有效时间和 FPS 估算，并记录警告。零间隔表示逐帧采样。
- 本机逐解码帧计算小尺寸画面的颜色、亮度变化，不调用模型。已检测的镜头边界会截断窗口。完全位于两个网格采样点之间的短镜头补采一张首帧。
- 候选与上次选中的目标在全图及局部网格均高度相似才跳过；保留变化帧，稳定画面默认每三个基准采样周期复查，镜头首尾采样目标总是保留。
- 选中帧按时间顺序分组，每窗最多三张，不重复滑动。同镜头 `A B C D E F` 变成 `ABC`、`DEF`；镜头末尾可只有一至两张。每窗默认最长十秒，达到上限后新窗必须有自己的观察帧。
- 被跳过的相似采样点可以延长当前窗口的覆盖终点。区间只使用实际采样点，不推算未采样的镜头终点。

## 审核与连续命中

- Qwen 请求内所有 `FRAME 1/2/3` 都是审核目标；任何图片出现的风险细节都须保留。一次汇总描述交给 Guard 判定，不再逐目标滑动或追加目标单图复核。
- OCR、人脸分别检查窗口内最多三张所选图片。后两张出现的新字幕、新人物都可以命中；不能将同一镜头简单等同为同一字幕或同一人物。
- 窗口内任一选中帧命中，结果按该窗口 `开始~结束` 视为连续命中。例如 0、1、2 秒组成一窗，2 秒命中时输出 `00:00:00.000~00:00:02.000`。这是窗口级归因，不代表逐帧确认了人物或内容的实际持续时间。
- 相邻同镜头窗口中，同来源、同风险类别均命中时延长区间，OCR 和视觉描述不再要求逐字一致；人脸额外要求人物名称一致。例如 `15~17`、`18~19` 合为 `15~19`，覆盖采样点之间的间隙。安全窗、缺失窗、切镜、该类别未命中或超过采样间隔容差会打断合并；不能用另一来源的命中证明连续性。
- 连续结果保留去重后的全部描述，并通过 `evidence` 保存各窗口的原始描述与时间。相同或完全包含的结果区间进一步合为一条，`findings` 保留各项原始类别、来源、时间、证据和人脸位置。部分重叠但互不包含的区间维持独立。
- WebUI、综合审核 HTTP/WebSocket 返回、任务详情和 JSON/ZIP 下载使用相同分组规则。筛选类别时恢复子项自己的时间范围。旧任务无需重新调用模型即可合并相同或包含区间；旧结果缺少镜头与窗口关联信息，不会仅凭一秒间隙推测连续性，新任务在后端按实际窗口合并。
- 人脸框保留每张实际检测帧的 `time_ms`，即使复用识别结果也采用当前帧时间，避免回看定位错位。整窗模式额外保存未取整的 `pts_seconds`、解码序号 `frame_index` 和 `duration_seconds`；帧时长取相邻解码 PTS 差，末帧使用 FPS 估计。

## 人脸框与播放帧同步

- 点击命中记录或上一/下一采样帧时，使用精确 PTS 加半帧时长定位（偏移最多 20 毫秒），避免落在切镜前的边界。旧任务只有取整的 `time_ms` 时向后偏移 1 毫秒，兼容已有结果，无需重跑审核。
- 人脸框仅在暂停且播放器实际显示的帧与检测帧一致时展示。时间来自 `requestVideoFrameCallback` 的 `mediaTime`，不使用请求跳转的 `currentTime` 推测画面，也不沿用原来的 45 毫秒邻帧容差。
- 跳转和切换视频时清空旧帧状态，并丢弃过期回调。不支持精确帧回调的浏览器会隐藏人脸框并提示；仍可播放视频和定位审核记录。
- 旧毫秒数据的匹配误差仅允许取整造成的约 0.5 毫秒；新 PTS 数据只容忍 10 微秒的序列化误差。窗口连续命中区间保持原义，人脸位置不会向窗口内未检测的帧传播。
- 回归样例：`test_pieces-2.mp4` 在 `495.233333…` 秒切镜，旧标记 `00:08:15.233` 曾显示切镜前一帧。浏览器实测旧结果跳至 `495.234` 秒后显示切镜后画面，人脸框与该帧一致。

## 请求复用与错误处理

- 缓存仅在当前任务内生效，有容量上限并在结束或取消时清理；并发相同请求合并为一次。
- OCR 按完全相同 JPEG 输入复用；人脸按完全相同尺寸和原始像素复用；Guard 按完全相同文字复用；视觉审核按有序图片内容组合复用，并使用当前窗口重新赋予时间区间。普通相似帧不会直接共享识别结论。
- 空 OCR 是成功结果，可复用且不调用 Guard。只有成功响应进入缓存，失败不会永久缓存。
- 某张图片 OCR 或人脸失败只记录该时间点未完成；视觉整窗失败记录窗口未完成。其余模块和后续窗口继续处理。
- Qwen 和 OCR 上限为 300 tokens，提示词明确要求总输出不超过 500 个中文字符（其他字符同样计入）；token 与字符数并非固定比例，实际可能更短。Guard 为 512。截断时保留已有内容，记录 WARNING，不因截断重试。有效 `Unsafe`、`Controversial` 均需审核；无法解析有效判定仍记录局部未完成。
- 多行提示词以 Markdown 标题、列表和加粗要求组织，源码保留缩进，在组装请求时逐段 `dedent(...).strip()`，保留换行与相对缩进。PaddleOCR 的用户任务标识仍为 `OCR:`，长度约束放在系统提示词；待审核原文不做提示词缩进清理。
- 每个任务使用三个窗口消费者，等待队列容量按并发数的两倍动态计算（当前为 6）。日志包含窗口数、选中帧数，各模块请求数和复用次数，便于核对请求节省。拼图 fallback 可能使一次视觉审核包含两次 HTTP 请求。

## 配置与兼容

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| `WCM_NSFW_REVIEW_MODE` | `window` | 整窗审核；`target` 恢复原目标帧审核，OCR/人脸也恢复固定网格 |
| `WCM_NSFW_WINDOW_MAX_SECONDS` | `10` | 整窗跨度上限，范围大于 0 且不超过 60 秒 |
| `WCM_NSFW_SAMPLING_MODE` | `scene` | 检测场景边界并筛除高度相似帧；`fixed` 保留全部网格帧 |
| `WCM_NSFW_SCENE_MAX_STRIDE` | `3` | 稳定画面的最大采样间隔倍数，范围 1～10 |
| `WCM_NSFW_SCENE_CUT_THRESHOLD` | `27` | 颜色/亮度切镜阈值，更低会分出更多边界 |
| `WCM_NSFW_IMAGE_MODE` | `auto` | 优先独立图片，仅在明确不支持多图时回退拼图；可强制 `multi_image` 或 `montage` |
| `WCM_NSFW_VERIFY_TARGET` | `false` | 仅旧 `target` 模式适用，整窗模式始终不追加单目标复核 |

Qwen 模型为 `WasuAI/Qwen3.8-27B-Abliterated`。整窗拼图保留各面板完整画面、相同分辨率上限和 `FRAME` 标识，仍审核全部面板。无关超时、鉴权或限流不会触发拼图请求。

`target` + `fixed` 完整保留旧版 `ABC`、`BCD`、`CD`、`D` 行为。单张图片和独立人脸检索接口保持原有处理方式；窗口策略适用于视频综合审核、NSFW 检测和文字审核。

## 验证范围

场景检测与相似度筛选是启发式，不能保证极小、短暂变化零漏检。窗口命中区间属于用户选择的连续归因策略，不能作为精确事件起止标注。请求减少比例也不等同于整条任务耗时减少比例。

回归覆盖三图全量审核、多图拼图 fallback、变化字幕/人物、相同输入并发复用、缓存淘汰和失败不缓存、时间区间及人脸框定位、局部失败隔离、取消清理、旧模式兼容。实际视频采样统计和合成图片模型测试见 [窗口审核评估](model-evaluations/2026-09-09-window-review.md)。
