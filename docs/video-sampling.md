# 三帧滑动窗口

视频审核、独立 NSFW、OCR 文本检测和人脸检索共用 `api/utils.py` 的 `VideoFrameSampler`。

- 保持采样间隔：帧步长为 `max(int(fps * sample_interval), 1)`，时间戳统一为源帧序号除以 FPS。无效 FPS 按原约定回退到 25，零间隔表示逐帧采样。
- 窗口长度 3，步长 1。例如采样帧 `A B C D` 产生 `ABC`、`BCD`、`CD`、`D`；每个采样帧恰好一次位于窗口第一位。
- 到视频末尾按实际剩余帧数提交，不补帧、不复制尾帧。不增加偏离原采样间隔的额外帧。只有 1 或 2 个采样帧的视频也能处理；没有采样帧时不请求模型。
- NSFW 将整个窗口的 2–3 帧按时间顺序拼成一张 JPEG，每次只发送一个图片字段，兼容单图模型。横屏画面上下排列，竖屏画面左右排列；加序号、采样时间和分隔线，保持比例、不裁剪，每帧长边最多 1024 像素。单帧直接使用原图，不重复编码。OCR、Face 和其它单帧任务只处理窗口第一帧，因此其采样覆盖率保持不变。
- 窗口结果仍标注第一帧时间；NSFW 提示词要求后续帧仅用于理解当前帧，避免把未来画面的风险提前标记。明确处理镜头切换、遮挡、不确定性和缺失上下文。
- 相邻窗口共享画面及 JPEG 编码，综合审核继续使用原有有界队列与并发消费者。解码失败或任务取消时释放视频句柄和消费者。

窗口功能不涉及前端或接口返回结构变更；图片输入仍作为单帧处理。

NSFW 提示词说明拼图顺序及辅助标签，要求模型将各格视为不同时刻的画面。图片解码、拼接失败或模型报错、超时会使审核失败并显示错误，不再把「无法获取描述」交给文本审核后误当作安全画面。
