这不是租约实际过期，也不是重复提交。过期回收的范围 UPDATE 会锁到仍然有效的 processing 记录。

## 修复

- 回收过期任务时，先用普通 SELECT 查候选 ID，再按主键顺序逐条 UPDATE。更新时重新检查状态和租约，避免覆盖并发完成、取消或续租。
- 领取任务、续租和保存结果遇到 MySQL 1213 时，分别以新连接重试数据库操作，最多重试 3 次，间隔 50/150/300 ms。
- 结果准备和证据上传只执行一次；保存重试仍检查 processing 状态、执行令牌和租约期限。失败的旧执行者不能覆盖当前任务。
- 记录数据库操作名、任务 ID、MySQL 错误码和重试次数，日志不写 SQL 参数。

该重试仅针对 InnoDB 已回滚事务的死锁。连接中断、锁等待超时等错误不自动重放；死锁重试耗尽后仍进入现有失败处理。这次不增加表结构或修改模型审核流程。

依据：[MySQL 死锁处理](https://dev.mysql.com/doc/refman/8.4/en/innodb-deadlocks-handling.html)、[InnoDB 错误及回滚范围](https://dev.mysql.com/doc/refman/8.4/en/innodb-error-handling.html)。
