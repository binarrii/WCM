# 视频审核吞吐优化（2026-09-14）

本次优化整窗视频审核的解码、图片预处理和困难人脸补帧，并为视觉、OCR、Guard 增加 worker 级 HTTP 连接池。

## 行为

- 主采样的 OpenCV 打开、迭代和关闭都在同一专用线程执行。异步任务按需读取，原有窗口队列继续提供容量上限；取消时先等待当前解码调用退出、关闭解码器，再删除临时视频。
- 视觉图片直接从主采样的原始像素等比例缩小并编码一次，最长边仍为 896。OCR 继续使用独立的原尺寸 JPEG，人脸继续使用原始像素。编码和图像散列在线程中进行，三个审核分支仍独立处理失败。
- 困难人脸补帧仍在主审核结束后开始，沿用原有时间点选择、每窗上限、全视频 30% 预算和识别阈值。相邻目标的解码范围重叠时复用连续解码，分离的区间才重新定位。保留真实 PTS，重复 PTS 只识别一次。
- 补帧不再先收集全部图片。解码一帧即可开始识别，`face_neighbor_concurrency` 为正数时限制在途补帧任务数，为 ≤ 0 的整数时不限制补帧并发；补帧总量预算仍有效。未读取到帧和重复 PTS 的目标也会推进处理进度。取消或模型失败保护触发时关闭解码器并取消剩余请求。
- 视觉、OCR、Guard 按模型分别复用当前 worker/event loop 的 HTTPX 客户端，应用退出时关闭。请求 URL、鉴权和超时仍在每次请求时读取，运行时配置更新不要求重建连接池。没有 API lifespan 的独立调用创建并关闭自己的客户端，不跨 `asyncio.run` 共享连接。

旧 target 模式保留原有采样和图片处理流程；模型连接池同时覆盖该模式。此次没有调整任务/窗口并发、采样密度、JPEG 质量、模型或提示词。

## 验证

- Python 默认测试集：610 passed，7 个 live 测试按默认规则跳过。
- 新增覆盖连接池复用与关闭、运行时超时刷新、事件循环响应、同线程解码清理、取消/背压、补帧边解码边识别、临近帧真实 PTS 去重和视觉单次编码。
- 合成 H.264 视频：960×540、30 FPS、12 秒、GOP 90；58 个补帧目标，间隔 0.2 秒。使用改动前后的读取函数各运行三轮：

| 补帧读取 | 三轮耗时（秒） | 中位数 |
| --- | --- | --- |
| 改动前逐目标定位 | 0.846、0.763、0.768 | 0.768 |
| 改动后合并定位 | 0.092、0.101、0.085 | 0.092 |

该样本的补帧读取中位耗时减少约 88%，58 帧的目标时间、实际 PTS 和像素逐项一致。这是本机解码环节的对照，不代表整条真实审核任务提速 88%；模型服务负载、视频编码和补帧分布会影响实际收益。
