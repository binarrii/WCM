# OCR 截断导致文字审核未完成

## 任务与原因

- 任务：`be08e645-e0a1-4216-8def-c249d4250d99`，视频 `test_pieces-2.mp4`。
- 结果含 59 个文字审核未完成项；旧日志只能定位到 `ocr:ValueError`。
- 原来的“模型响应或帧数据无效”将多种解析错误合并，不能据此认定视频帧损坏。
- 经用户授权，仅以 0、10、74、580 秒各一帧，对比原提示与官方 `OCR:` 任务提示。目的地为项目现有 `WasuAI/PaddleOCR-VL-1.6`，识别文字交给现有 `WasuAI/WasuGuard-Gen-4B`。

格式依据：[PaddleOCR-VL-1.6 官方模型卡](https://huggingface.co/PaddlePaddle/PaddleOCR-VL-1.6)。本次同时改变了提示内容及图片/文本顺序，未单独消融两者影响。

## 修复与边界

- 使用官方 OCR 任务格式；保持 1024 tokens 上限，不增加失败重试。
- 单独记录 OCR / 安全判定模型及具体原因：截断、响应字段异常、无有效判定等。
- 正常结束且 OCR 文字为空时，跳过文字安全判定；其他审核模块照常工作。
- 模型响应错误仍由帧级隔离逻辑捕获，不使整个长视频任务失败。
- 只验证了获准的四个时间点，不能据此证明全部 59 项或所有 OCR 识别准确率已解决。纯白合成图仍观察到文字幻觉，因此“请求正常完成”不等于“文字完全正确”。
- 旧任务结果保持不变；未重跑整条视频，也未将历史未完成项直接改成安全。
