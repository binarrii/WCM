# 地图对象核查验收与模型限制

模型仍为 WasuAI/Qwen3.8-27B-Abliterated，一张图片一次混合对象请求。
生产提示词与结构化结果见 [live-results.json](live-results.json)。没有重跑或修改用户历史任务。

## 实测

使用 8 个程序绘制的简化地图正反例，按生产上限处理至最长边 1080，JPEG 质量使用当前参数。
只向模型发送像素和生产提示词，不发送样例名称、预期问题或预期数量。
几何数据来源和地名对照来源见 [sources.json](sources.json)。这些是测试示意图，不是官方标准地图。

| 样例 | 预期 | 实际 |
| --- | --- | --- |
| 完整中国轮廓 | 无命中 | 误报新疆缺失 |
| 去除台湾岛轮廓 | 台湾缺失 1 | 检出 1 |
| 台湾填色并用国别图例明确标为日本 | 外国归属表示 1 | 检出 1 |
| 中俄边境图两城市仅标现名 | 中文旧称缺失 2 | 检出 2 |
| 同图两城市已加中文旧称括注 | 无命中 | 误报缺少旧称 2 |
| 中国地图裁切局部 | 无命中 | 误报台湾缺失 |
| 法国地图 | 无命中 | 无命中 |
| 仅有两个城市名的词语练习 | 无命中 | 无命中 |

类别/数量吻合为 5/8；这不是准确率估计，更不代表所有关注区域都有可靠识别能力。
新疆误报依赖轮廓猜测，地名误报遗漏了实际可见括注，裁切图误报把局部当全图。
生产提示词已明确排除这些情况，但本模型仍可能不遵从。结果只作为待复核发现，不自动判违规。

额外比较了地图专用请求、候选二次核验、原图加四个放大局部、提交前反证提示。
二次核验能去掉部分误报，却把真实缺台湾样例也否定；放大没有解决该漏检且会增加请求成本。
地图专用提示词漏掉旧称缺失和台湾缺失；附加反证提示仍有 3 个负例误报。
因此未将这些试验方案加入生产调用流程。对应 probe-*.json 保留完整结果，未删除失败样例。

框沿用 0–1000 归一化解析：缺失区域只能定位承载问题的地图，不能为不存在的区域生成真实框。
具体标签/地图局部的模型框也可能偏移，本次没有修改坐标换算、人脸框或小对象 64px 规则。

## 流程验证

- 后端 959 项通过、7 项跳过；本机 socket 测试需允许 Unix socket 绑定。
- 前端 129 项通过，生产构建通过，Ruff 检查通过。
- 图片和窗口视频混合对象发现、7 个区域与 3 类领土问题、8 组地名、简繁体括注过滤、非法范围失败均有回归。
- 地图元数据在保存合并、分类筛选、JSON 导入导出、采样帧跳转中保留。
- 浏览器确认大地图蓝色四角框、小地图圆环十字标及点击浮层开关；人脸原框保留，无运行错误。
