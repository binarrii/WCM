# 人物合并与追加照片

新增人物点击「确认提交」时，先在总库跨类别查询同名档案（忽略姓名两端空格和英文大小写，完整姓名匹配）。有同名记录时显示本次照片及已有档案的照片、ID、类别和备注，用户可以选择「合并到所选人物」或「仍然新建人物」，也可返回修改。合并仅将照片追加到选定 ID，已有档案信息保持不变。查询失败时保留表单并停止提交。

`GET /api/v1/face_records/name_matches?name=姓名` 返回全部同名档案。WebUI 新建请求发送 `check_name=true`，后端在写锁内再次检查，发现同名时返回 `409` 和候选档案；仅用户选择仍然新建时发送 `check_name=false`。已有脚本未传该字段时保持原注册行为。

人物库页面点击「人物合并」，勾选 2–20 个属于同一个人的档案，点击「合并所选人物」，选择要保留的 ID 后确认。保留档案的姓名、类别、备注和其它元数据不变；其它档案的照片归入该 ID，重复内容的原图只保留一个图库入口。总库和分类库的人脸索引一起更新。

人物卡片底部的图片按钮为「追加照片」。窗口显示姓名和已有 ID，选择或粘贴照片、裁剪并确认后注册到该人物。每次追加一张，必须包含单张清晰人脸；重复上传完全相同的图片不会重复注册。

- `POST /api/v1/face_records/merge`，JSON：`{"target_id":"保留ID","source_ids":["被合并ID"]}`。
- `POST /api/v1/face_records/{id}/images`，multipart 字段 `file`。
- 返回 `record`（与人物列表相同结构）、`added_images` 和 `merged_ids`。图片 URL 只暴露公开图片路径。

合并需要原始照片完整可读，缺失时会在写入前拒绝操作。已有分类库中的旧 ID 会通过兼容映射查找。图库写入通过文件锁跨 API worker 串行执行，查询仍可进行；外部导入脚本应避开人物编辑窗口。

历史审核结果保留当时的人物快照与 ID，不追溯改写。合并不会删除源照片文件，因此历史图片链接继续可用。后续检索使用保留人物及合并后的图库。

每次写入在图片卷 `/tmp/wcm/.person-operations/` 保存 JSON 操作记录，包含人物元数据快照及原人脸 ID。正常失败会补偿新增样本、元数据和已删除源档案；恢复源档案时会重新注册其全部原图，因此样本人脸 ID 和创建时间可能改变，人物 ID 保持一致。记录状态为 `completed`、`rolled_back` 或 `recovery_required`；进程异常退出也可能留下 `prepared` / `target_ready`。若出现未完成恢复，应按操作编号检查快照和对应集合，先恢复源人物、再清理目标新增样本，核对所有照片后再重试，勿删除操作记录或原图。
